# webkitgtk-android

GTK 4 widget that embeds Android System WebView behind a small WebKitGTK-shaped `WebView` API. It is the Android counterpart of webview2-gtk: a Vala app can construct a `WebView`, load a URI, and read load signals the same way it does with WebKitGTK on Linux.

The library also exposes host calls for an accessibility dump, fill, and press. Those walk the Android accessibility tree. They do not inject page JavaScript.

A version tag builds this library and publishes it as a Pixie file. The pin list for that file is generated by the release build and published only at [release.pins](https://roojs.github.io/webkitgtk-android/release.pins). It is not stored in this repository.

## Use

Depend on `webkitgtk-android-1` after the Pixie sysroot is installed. The archive carries `libwebkitgtk-android-1.so`, the pkg-config file, the VAPI, the host headers, and the Java sources under `share/pixiewood/webkitgtk-android-java`.

```vala
#if ANDROID
using WebKitGtkAndroid;
#endif

var web = new WebView ();
web.load_uri ("https://roojs.com/");
```

Copy `share/pixiewood/webkitgtk-android-java` into the app's Java tree. Those classes (`WebViewHost` and the accessibility, download, and freeze helpers) must be in the same APK as `libwebkitgtk-android-1.so`. JNI loads them from that APK's class loader.

## Limitations

- Android only. There is no Linux or Windows build of this library.
- The API is a subset of WebKitGTK: navigation, URI and title, load signals, cookies, and downloads. It does not include the inspector, extensions, custom URI schemes, or printing.
- No screenshots, PDF export, or other page capture.
- Accessibility is the raw dump, fill, and press calls. Turning that tree into markdown stays in the application.
